2. Arquitectura propuesta

Capas de la arquitectura

Capa de presentación: Power App embebida como pestaña en Teams. El equipo accede desde el canal Agile. Sin instalación de app adicional, sin aprobación de admin si se usa como Tab URL.

Capa de lógica: Power Automate flows orquestan el proceso: reciben datos de la Power App, invocan la API de ICA/watsonx, preparan el resumen, esperan confirmación humana, luego llaman a la Monday API y/o al webhook de Slack.

Capa de datos primaria: SharePoint Lists dentro del mismo tenant IBM. Almacenamiento seguro, sin salida de datos a servicios externos sin autorización. Datos: sesiones, bloqueantes, retrospectivas, showcases, votos.

Capa de datos secundaria: Monday.com como sistema de registro Agile visible para stakeholders. Los datos van a Monday solo con confirmación explícita del usuario.

Capa de IA: IBM Consulting Advantage (ICA) vía navegador para uso manual, o watsonx.ai API para integración programática desde Power Automate.

Capa de comunicación: Slack Incoming Webhook para publicaciones aprobadas. El mensaje es generado por la app y enviado solo con doble confirmación.

3. Flujo completo de información

Flujo A — Generar resumen de reunión

Paso 1 · Usuario abre la Power App desde la pestaña fijada en Teams
↓
Paso 2 · Selecciona tipo de sesión: Reunión General | Sesión Agile | Retrospectiva | Showcase | Otra
↓
Paso 3 · Selecciona la iteración / periodo (lista desplegable desde SharePoint)
↓
Paso 4 · Pega o carga transcripción / notas / acuerdos (campo de texto largo)
↓
Paso 5 · Presiona "Generar Resumen" → Power Automate envía el texto al endpoint de watsonx.ai o ICA. El prompt estructurado garantiza el formato esperado.
↓
Paso 6 · La app muestra la vista previa del resumen estructurado
↓
Paso 7 · Usuario revisa, edita campos individuales o elimina secciones. Todos los campos son editables antes de guardar.
↓
Paso 8 · Usuario presiona "Confirmar y Guardar" → registro en SharePoint List (timestamp, autor, iteración)
↓
Paso 9 · Aparece opción: "¿Enviar también a Monday?" → Solo si usuario confirma → Monday API crea item en tablero correspondiente
↓
Paso 10 · Aparece opción: "¿Generar versión para Slack?" → Se muestra preview del mensaje corto
↓
Paso 11 · Segunda confirmación explícita: "Publicar en Slack" → POST al Incoming Webhook del canal correspondiente
↓
Paso 12 · Log de auditoría: quién hizo qué, cuándo, sobre qué sesión → columna en SharePoint

Flujo B — Registrar Bloqueante

Usuario abre formulario → completa campos obligatorios (nombre, tipo, impacto, urgencia) → guarda en SharePoint → opcionalmente envía a Monday → si "Requiere atención gerencial" está marcado, se genera una notificación Adaptive Card al gerente en Teams.

Flujo C — Canicas del Humor

El gerente de iteración activa la votación desde la app → se genera un Microsoft Form con las opciones de color → los integrantes votan (1 voto por persona por sesión, verificado por SharePoint) → al cerrar, la app calcula porcentajes y muestra gráfico → resultado guardado en SharePoint → opcionalmente en Monday → tendencia comparativa disponible en el dashboard.

Flujo D — Retrospectiva

Cada integrante agrega comentarios por categoría (qué se hizo bien / qué salió mal / qué mejorar / preguntas abiertas) → el facilitador puede marcar comentarios como "Acción de mejora" → la acción se convierte en registro con responsable + fecha + estado → seguimiento automático en la siguiente retrospectiva.

Implementación de permisos en SharePoint

  • SharePoint List → Configuración → Permisos avanzados → grupos por rol
  • Power App usa User().Email para identificar al usuario y mostrar u ocultar controles según el rol en la lista de configuración
  • Las listas de datos tienen permisos de lectura general y escritura solo para el rol correspondiente

Trazabilidad de exportaciones

Cada acción de envío a Monday o Slack queda registrada en una SharePoint List "AuditLog" con: usuario, timestamp, tipo de acción, ID de sesión, estado (enviado / rechazado / editado). No se puede eliminar este log desde la Power App.

Seguridad de datos IBM

  • Todos los datos primarios permanecen en el tenant IBM (SharePoint, OneDrive)
  • Los datos enviados a Monday solo incluyen resúmenes estructurados, sin transcripciones completas
  • La API key de watsonx.ai se almacena en Power Automate como variable de entorno segura (no en código)
  • El webhook de Slack se almacena de la misma forma
  • No se utilizan cuentas personales para ningún almacenamiento
  • Monday.com debe usarse con la cuenta corporativa IBM, no con cuenta personal

8. Prompt definitivo para resumir reuniones

Este prompt debe ser usado con ICA o con la API de watsonx.ai (modelo ibm/granite-13b-instruct-v2 o meta-llama/llama-3-1-70b-instruct).

INSTRUCCIÓN DEL SISTEMA: Eres un asistente especializado en documentación de reuniones Agile para equipos de consultoría IBM. Tu función es generar resúmenes estructurados, precisos y profesionales a partir de transcripciones, notas o acuerdos de reuniones. REGLAS OBLIGATORIAS: 1. 11. Instrucciones de instalación paso a paso

Fase 1 — Preparar SharePoint (30 min)

1
Ir a sharepoint.com con cuenta IBM → Crear nuevo sitio de equipo → Nombre: "Agile Team Hub"
2
Crear las 8 listas SharePoint con los campos definidos en la sección 10 (usar plantilla personalizada)
3
Configurar permisos: compartir el sitio con todos los integrantes del equipo (rol: Miembro). El gerente y el owner tienen rol de Propietario.
4
Crear la primera iteración en ATH_Iteraciones y el primer gerente en ATH_Gerentes

Fase 2 — Configurar IBM Cloud / watsonx (20 min)

1
Ir a cloud.ibm.com con credenciales IBM (w3id) → Crear proyecto en watsonx.ai
2
Generar API key: cloud.ibm.com → Manage → Access → API Keys → Create
3
Anotar: API Key, Project ID, región (us-south o eu-de)
4
Probar el prompt en Prompt Lab de watsonx.ai con una transcripción de ejemplo

Fase 3 — Configurar Slack Webhook (10 min)

1
En Slack: ir al canal donde se publicarán los resúmenes → Configuración → Integraciones → Incoming Webhooks
2
Crear nuevo webhook → Copiar la URL generada
3
Guardar la URL como Environment Variable en Power Automate (no en texto visible)

Fase 4 — Crear la Power App (45 min)

1
En Teams → canal Agile → + pestaña → Power Apps → Crear nueva app
2
Conectar fuentes de datos: SharePoint (sitio Agile Team Hub) → seleccionar las 8 listas
3
Crear pantalla principal con los 9 botones según diseño de la sección 6
4
Crear cada sub-pantalla (Resumen, Bloqueante, Canicas, Showcase, Retro, Acciones, Dashboard)
5
Conectar botón "Generar con IA" al Power Automate flow de watsonx
6
Conectar botón "Publicar en Slack" al Power Automate flow de Slack (con confirmación)
7
Guardar y publicar la app → Compartir con el equipo

Fase 5 — Configurar Power Automate flows (30 min)

1
Crear Flow "ATH-Resumen-IA": disparado desde Power Apps → llama HTTP watsonx → devuelve JSON → guarda en SharePoint
2
Crear Flow "ATH-Publicar-Slack": disparado desde Power Apps → HTTP POST al webhook → registra en AuditLog
3
Crear Flow "ATH-Bloqueante-Critico": trigger SharePoint → Teams notification
4
Crear Flow "ATH-Recordatorio-Semanal": scheduled → filtra acciones vencidas → Teams message
5
Agregar API key de watsonx y webhook URL como Environment Variables en Power Automate

Fase 6 — Fijar para el equipo (5 min)

1
En el canal Agile de Teams → + pestaña → Power Apps → seleccionar "Agile Team Hub" → Guardar
2
Notificar al equipo que la pestaña está disponible en el canal
3
Si se necesita ícono en la barra lateral: solicitar al Teams Admin que fije la app via App Setup Policy

Fase 7 — Configurar Monday.com (20 min)

1
Verificar si existe cuenta Monday corporativa IBM → si sí, crear espacio "Agile Team Hub" con los 5 tableros
2
Obtener Monday API key: cuenta Monday → Developer → API → Generate Key
3
Agregar Monday API key como Environment Variable en Power Automate
4
Crear Board IDs de cada tablero y registrarlos en ATH_Iteraciones de SharePoint

13. Riesgos y limitaciones

RiesgoProbabilidadImpactoMitigación
Política IBM no permite sideload de apps en TeamsMediaMedioUsar Tab URL en canal. No requiere sideload.
Monday.com sin contrato corporativo IBM (solo 2 seats)AltaAltoUsar SharePoint Lists como sistema primario + Power BI para dashboard. Monday como secundario opcional.
Cuota de watsonx.ai Lite superadaMediaMedioUsar ICA manualmente para el prompt. Alternativa: copy-paste del JSON generado en ICA.
Slack Enterprise Grid restringe webhooks entrantesBajaAltoCoordinar con Slack Workspace Admin para habilitar el webhook del canal. Es política de configuración, no licencia.
Power Automate HTTP connector bloqueado por políticaBajaAltoUsar conector estándar de Power Automate en lugar de HTTP si IBM restringe llamadas HTTP externas.
Privacidad: transcripciones enviadas a watsonxAltaAltowatsonx.ai en IBM Cloud es aprobado para uso interno IBM. Nunca enviar datos a servicios externos no aprobados. Documentar en política del equipo.
Anonimato en votos de canicas no garantizable al 100%MediaMedioEl owner de SharePoint podría ver los registros. Documentar y acordar con el equipo el nivel de anonimato real.
